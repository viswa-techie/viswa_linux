## 12.1 GRUB Bootloader

**GRUB** (GRand Unified Bootloader) is the standard bootloader for x86 Linux desktops and servers.

```
GRUB Boot Stages:

Stage 1 (boot.img)            Stage 1.5 (core.img)         Stage 2 (normal.mod)
┌────────────────────┐       ┌──────────────────────┐     ┌─────────────────────┐
│ MBR: 446 bytes     │       │ /boot/grub/core.img  │     │ /boot/grub/          │
│ or ESP: grubx64.efi│  ──►  │ Filesystem drivers   │ ──► │ Full GRUB            │
│ Knows where 1.5 is │       │ Can read /boot/grub/ │     │ Menu, scripting      │
│                    │       │                      │     │ Module loading       │
└────────────────────┘       └──────────────────────┘     └─────────────────────┘
                                                                   │
                                                                   ▼
                                                          Load vmlinuz + initramfs
                                                          Jump to kernel
```

GRUB configuration:

```bash
# /boot/grub/grub.cfg (auto-generated by grub-mkconfig)

menuentry 'Ubuntu 24.04' --class ubuntu {
    set root='hd0,gpt2'
    linux /vmlinuz-6.8.0-40-generic \
        root=UUID=abcd-1234 ro quiet splash
    initrd /initrd.img-6.8.0-40-generic
}

menuentry 'Ubuntu 24.04 (recovery)' --class ubuntu {
    set root='hd0,gpt2'
    linux /vmlinuz-6.8.0-40-generic \
        root=UUID=abcd-1234 ro single
    initrd /initrd.img-6.8.0-40-generic
}
```

```bash
# Generate GRUB configuration
sudo grub-mkconfig -o /boot/grub/grub.cfg

# Install GRUB to disk (UEFI)
sudo grub-install --target=x86_64-efi --efi-directory=/boot/efi

# Install GRUB to disk (legacy BIOS)
sudo grub-install /dev/sda

# GRUB commands in interactive shell
grub> ls                          # List devices/partitions
grub> ls (hd0,gpt2)/              # List files
grub> cat (hd0,gpt2)/etc/os-release
grub> set root=(hd0,gpt2)
grub> linux /vmlinuz root=/dev/sda2
grub> initrd /initrd.img
grub> boot
```

## 12.2 U-Boot Bootloader

**U-Boot** (Das U-Boot) is the standard bootloader for embedded Linux — ARM, MIPS, RISC-V, PowerPC.

```
U-Boot Architecture:

┌────────────────────────────────────────────────────────┐
│                    U-Boot                               │
│                                                        │
│  ┌──────────────────────────────────────────────────┐  │
│  │  Command Shell (CLI)                              │  │
│  │  => help, printenv, setenv, boot, tftpboot, ...  │  │
│  └──────────────────────────────────────────────────┘  │
│                                                        │
│  ┌─────────┐ ┌─────────┐ ┌─────────┐ ┌────────────┐  │
│  │ MMC/SD  │ │  NAND   │ │  NOR    │ │  Network   │  │
│  │ driver  │ │ driver  │ │ driver  │ │  (TFTP)    │  │
│  └─────────┘ └─────────┘ └─────────┘ └────────────┘  │
│                                                        │
│  ┌─────────┐ ┌─────────┐ ┌─────────┐ ┌────────────┐  │
│  │  USB    │ │  UART   │ │  SPI    │ │  I2C       │  │
│  │ driver  │ │ console │ │ driver  │ │  driver    │  │
│  └─────────┘ └─────────┘ └─────────┘ └────────────┘  │
│                                                        │
│  ┌──────────────────────────────────────────────────┐  │
│  │  Device Tree / Platform Support                   │  │
│  │  Board-specific initialization (board_init())     │  │
│  └──────────────────────────────────────────────────┘  │
└────────────────────────────────────────────────────────┘
```

U-Boot commands and boot:

```bash
# U-Boot interactive shell
=> help                              # List all commands
=> printenv                          # Show all environment variables
=> version                           # U-Boot version info

# Environment variables
=> setenv bootargs "console=ttyS0,115200 root=/dev/mmcblk0p2 rootwait"
=> setenv bootcmd "mmc dev 0; fatload mmc 0:1 0x48000000 Image; \
   fatload mmc 0:1 0x49000000 board.dtb; booti 0x48000000 - 0x49000000"
=> saveenv                           # Save to persistent storage

# Load kernel from SD card
=> mmc dev 0                         # Select MMC device 0
=> mmc info                          # Show card info
=> fatload mmc 0:1 0x48000000 Image  # Load kernel
=> fatload mmc 0:1 0x49000000 board.dtb  # Load DTB

# Load kernel from network (TFTP)
=> setenv ipaddr 192.168.1.100       # Board IP
=> setenv serverip 192.168.1.1       # TFTP server
=> tftp 0x48000000 Image             # Download kernel
=> tftp 0x49000000 board.dtb         # Download DTB

# Boot kernel
=> booti 0x48000000 - 0x49000000     # ARM64: booti kernel - dtb
=> bootm 0x48000000                  # Boot FIT image or uImage
=> boot                              # Run bootcmd

# Memory operations
=> md.l 0x48000000 0x10              # Memory display (long)
=> mw.l 0x48000000 0xDEADBEEF        # Memory write
=> cmp.l 0x48000000 0x49000000 0x100 # Memory compare

# Flash operations
=> sf probe 0                        # Select SPI flash
=> sf read 0x48000000 0x100000 0x800000  # Read from flash
=> sf write 0x48000000 0x100000 0x800000 # Write to flash
```

U-Boot boot scripts:

```bash
# boot.scr (compiled boot script)
# Source: boot.cmd → mkimage -T script -C none -d boot.cmd boot.scr

echo "Loading kernel..."
fatload mmc 0:1 ${kernel_addr_r} Image
echo "Loading DTB..."
fatload mmc 0:1 ${fdt_addr_r} board.dtb

# Optional: load device tree overlay
fatload mmc 0:1 ${fdtoverlay_addr_r} camera-overlay.dtbo
fdt addr ${fdt_addr_r}
fdt resize 8192
fdt apply ${fdtoverlay_addr_r}

echo "Booting Linux..."
setenv bootargs "console=ttyS0,115200 root=/dev/mmcblk0p2 rootwait rw"
booti ${kernel_addr_r} - ${fdt_addr_r}
```

## 12.3 Barebox Bootloader

**Barebox** (formerly U-Boot v2) is a modern alternative to U-Boot with a more Linux-like codebase.

```
Barebox vs U-Boot:

Feature         U-Boot                  Barebox
─────────────────────────────────────────────────────
Code style      Custom                  Linux-like (kconfig, DT)
Shell           Simple (hush)            POSIX-like shell
Filesystem      Basic (FAT, ext2)       Full VFS (ext4, UBIFS, NFS)
Device model    Flat                     Linux-like driver model
Config          Kconfig                  Kconfig
Debugging       printf-based             Timeline, mem-debugging
Fastboot        Supported               Supported
Popularity      Very wide               Growing, NXP/Pengutronix
```

## 12.4 Bootloader Configuration

### U-Boot Configuration System

```bash
# U-Boot configuration follows Linux's Kconfig model

# Select default config for a board
make CROSS_COMPILE=aarch64-linux-gnu- imx8mm_evk_defconfig

# Customize configuration
make CROSS_COMPILE=aarch64-linux-gnu- menuconfig

# Build U-Boot
make CROSS_COMPILE=aarch64-linux-gnu- -j$(nproc)

# Output:
#   u-boot.bin          ← Raw binary
#   u-boot.img          ← U-Boot image with header
#   SPL                 ← Secondary Program Loader
#   u-boot-dtb.bin      ← U-Boot with embedded DTB
```

### Bootloader Comparison

| Feature | GRUB | U-Boot | Barebox | coreboot |
|---------|------|--------|---------|----------|
| Primary target | x86 PC | ARM/MIPS embedded | ARM embedded | x86 firmware |
| Architecture | x86, ARM, RISC-V | ARM, MIPS, x86, PPC | ARM, MIPS, x86 | x86 |
| Size | 2-10 MB | 0.5-2 MB | 0.5-2 MB | 256 KB-2 MB |
| Shell | grub-shell | hush shell | POSIX-like | None (payload) |
| Network boot | PXE, TFTP | TFTP, NFS, HTTP | TFTP, NFS | Via payload |
| Filesystem | ext2/3/4, fat, xfs | fat, ext2/4, ubifs | Full VFS | Minimal |
| Secure Boot | UEFI Secure Boot | FIT image signing | Image signing | Measured boot |
| DT support | Limited | Full (fdtcontroladdr) | Full (native) | ACPI |
| Development | Shell scripts | C + DT + env | C + DT + scripts | C + payloads |

## Interview Questions

**Q1: What is the difference between GRUB and U-Boot?**
A: GRUB is designed for x86 PCs with UEFI/BIOS — it reads filesystems, shows menus, and loads kernels from disk. U-Boot targets embedded systems (ARM, MIPS) — it initializes board hardware, supports TFTP/NFS boot, handles device trees, and runs from SRAM/DRAM. GRUB assumes standardized PC hardware; U-Boot requires per-board customization.

**Q2: How does U-Boot find and load the kernel on an embedded system?**
A: U-Boot follows the `bootcmd` environment variable, which typically: (1) selects the storage device (`mmc dev 0`), (2) loads the kernel to a memory address (`fatload mmc 0:1 $addr Image`), (3) loads the DTB, (4) sets `bootargs` (kernel command line), and (5) boots with `booti $kernel - $dtb`.

**Q3: What is an SPL and why is it needed?**
A: SPL (Secondary Program Loader) is a minimal first-stage bootloader that fits in SoC SRAM (usually 64-256 KB). Its only job is to initialize DRAM and load the full U-Boot into DRAM. It's needed because the Boot ROM can't hold the full bootloader, and DRAM isn't available until initialized.

**Q4: What is a FIT image in U-Boot?**
A: FIT (Flattened Image Tree) packages kernel, DTB, initramfs, and signatures into a single image using device tree syntax. It supports: multiple configurations (different DTBs for different boards), hash verification, digital signatures for secure boot, and multiple image types. Loaded with `bootm` command.

## Summary

- GRUB: standard x86 PC bootloader with filesystem access, menus, and scripting
- U-Boot: standard embedded bootloader with shell, TFTP, DT support, and per-board customization
- Barebox: modern alternative to U-Boot with Linux-like internals
- SPL is a minimal first-stage loader that initializes DRAM for the full bootloader
- U-Boot environment variables (`bootcmd`, `bootargs`) control the boot process
- FIT images bundle kernel + DTB + initramfs with integrity verification
